# Guía de Arquitectura y Manejo de Excepciones — `communities-service`

Este documento detalla la estrategia centralizada de gestión de errores, la estructura del DTO de error, los criterios de seguridad aplicados y la matriz de trazabilidad entre las excepciones de dominio y los **Casos de Uso (CU-41 al CU-54)**.

---

## 1. Estrategia y Principios de Seguridad

1. **Gestión Centralizada con `@RestControllerAdvice`:**

   * Toda excepción lanzada en cualquier capa (Repositorio, Servicio, Controlador) es interceptada centralizadamente por la clase `GlobalExceptionHandler`.
   * Garantiza un formato de respuesta JSON único y predecible en toda la API REST.
2. **Prevención de Fuga de Información (*Information Leakage*):**

   * **Protección contra Stack Traces:** Nunca se expone la traza de pila de Java ni la estructura interna de clases hacia el cliente en ningún entorno.
   * **Ocultamiento de Errores SQL:** Las excepciones no controladas de PostgreSQL (`DataIntegrityViolationException`, `SQLException`) o fallos imprevistos son capturados y registrados en el log interno del servidor con SLF4J (`log.error`), mientras que hacia la API pública se retorna una respuesta limpia HTTP 500 (*Internal Server Error*).
3. **Separación de Responsabilidades:**

   * El DTO de respuesta de error (`ErrorResponseDto`) reside estrictamente en el paquete `com.musa.communities_service.dto.response`, manteniendo la capa de excepciones libre de clases de transferencia de datos.

---

## 2. Estructura de Respuesta Estandarizada (`ErrorResponseDto`)

Todas las respuestas de error retornadas por el microservicio utilizan la estructura inmutable definida en `ErrorResponseDto`:

### Ejemplo de Respuesta JSON

```json
{
  "status": 400,
  "error": "Validation Error",
  "message": "Uno o más campos no cumplen las validaciones requeridas",
  "path": "/api/v1/communities",
  "timestamp": "2026-10-28T14:45:00Z",
  "details": [
    "El nombre de la comunidad es obligatorio",
    "El tipo de comunidad es obligatorio"
  ]
}
```

### Desglose de Atributos (`ErrorResponseDto`)


| Campo       | Tipo Java        | Descripción y Propósito                                                                                                                      |
| :---------- | :--------------- | :--------------------------------------------------------------------------------------------------------------------------------------------- |
| `status`    | `int`            | Código de estado HTTP numérico (400, 403, 404, 409, 500).                                                                                    |
| `error`     | `String`         | Nombre o categoría estándar del error HTTP (ej. "Not Found", "Bad Request").                                                                 |
| `message`   | `String`         | Explicación clara, concisa y segura orientada al usuario o desarrollador frontend.                                                            |
| `path`      | `String`         | URI o endpoint exacto de la petición HTTP donde se originó el fallo (`request.getRequestURI()`).                                             |
| `timestamp` | `OffsetDateTime` | Marca de tiempo exacta en la que se generó la excepción, formateada en ISO-8601 UTC (`ZoneOffset.UTC`).                                      |
| `details`   | `Liststring`     | Lista opcional de detalles específicos. Se utiliza en errores de validación`@Valid` para desglosar el campo con error y la regla incumplida. |
